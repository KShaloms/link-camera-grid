# ESP32-CAM 9칸 블록 유무 검사

카메라 한 대로 같은 크기의 3×3 지그를 촬영합니다. 1~9번 각각에 대해 없으면 0, 있으면 1을 제공합니다. 원본 프로젝트의 AI-Thinker 카메라 핀, Arduino 프레임워크, UART2, RS-485 자동 방향 모듈 조건을 사용합니다. 이 프로젝트는 9칸 판정 전용입니다. 기존 단일 물체 색상·크기 분류기는 원본 ZIP에 있습니다.

## 이 코드에서 말하는 ‘지그’와 찍어야 하는 네 점

사진 중앙에서 얇은 금속 칸막이가 가로·세로로 교차하여 9칸을 만든 **블록 보관판**입니다. 노란 번호표가 붙은 은색 바닥에 블록을 놓습니다. 클릭 대상은 이 아홉 칸을 모두 감싸는 **보관판 안쪽 바닥의 네 꼭짓점**입니다. 장비 전체의 알루미늄 프레임, 카메라 거치대, 흰색 부품통, 노란 번호표 중앙은 클릭 대상에서 제외합니다.

| 순서 | 가로 사진에서 클릭할 위치 (번호표가 1·2·3 / 4·5·6 / 7·8·9 순서일 때) |
| --- | --- |
| 1 | 1번 칸 왼쪽 위의 바닥 모서리 |
| 2 | 3번 칸 오른쪽 위의 바닥 모서리 |
| 3 | 9번 칸 오른쪽 아래의 바닥 모서리 |
| 4 | 7번 칸 왼쪽 아래의 바닥 모서리 |

카메라 화면이 돌아가면 방향도 달라집니다. 어느 방향에서 보든 실제 번호 1 → 3 → 9 → 7 순서를 따릅니다. 카메라는 노란 번호의 글자를 읽지 않습니다. 작업자가 알려준 네 점으로 9개 칸의 위치를 계산합니다.

**코드 읽는 예시**: 5번 칸에 블록을 놓으면 main.cpp의 measure()가 가운데 칸의 픽셀을 읽습니다. grid.h의 score()가 빈 판과의 변화율을 구하고 Cell::update()가 3프레임 연속 조건을 확인합니다. C++ 배열은 0부터 세므로 5번 칸은 cells[4]입니다. PLC가 40014를 읽으면 이 칸의 0 또는 1을 받습니다.

## 업로드와 첫 설정

1. ZIP을 풀고 VS Code에서 이 문서와 platformio.ini가 있는 폴더를 엽니다. PlatformIO의 esp32cam 환경을 선택합니다. src/wifi_config.h에 1_rapextender_2.4G 접속 설정이 들어 있으므로 사용할 공유기와 일치하는지 확인합니다.
2. ESP32-CAM을 MB에 장착하고 USB로 연결해 Build → Upload를 실행합니다. 업로드가 성공하면 노트북을 카메라와 같은 LAN에 연결하고 브라우저에서 http://link-cam2.local/ 을 엽니다. 시리얼 모니터(115200)에서 [WEB] 메시지로 이름 등록 상태를 확인할 수 있습니다.
3. 9칸과 지그 바닥 모서리가 모두 보이도록 카메라를 고정합니다. 손·블록·이송 기구를 치우고 운전 시 사용할 조명을 켭니다. ‘사진 갱신’을 누른 뒤 지그 **전체 바닥의 네 꼭짓점**을 1번 바깥 → 3번 바깥 → 9번 바깥 → 7번 바깥 순으로 클릭하고 ‘모서리 저장’을 누릅니다. 칸 중앙이나 칸막이 윗부분을 찍으면 검사 위치가 어긋납니다. 네 점은 재부팅 후에도 유지됩니다.
4. ‘빈 판 학습’을 누릅니다. 노출 적응 후 8프레임을 평균 내므로 ‘정상’이 될 때까지 빈 판을 유지합니다. 배경은 RAM에 있어 **전원을 다시 켤 때마다 빈 판 학습이 필요**합니다. 카메라가 그대로면 PLC에서 40009에 1을 한 번 쓰는 것으로도 가능합니다. 통상 운전에는 Wi-Fi가 필요하지 않습니다.
5. 35 mm 소형 블록을 1번부터 9번까지 한 칸씩 놓았다 빼며 해당 값만 0 → 1 → 0으로 바뀌는지 확인합니다. 가장 작은 흰 블록은 금속판과 밝기가 비슷할 수 있으므로 중앙과 가장자리에서 모두 시험합니다. 이어 1·3·4·9번을 동시에 채워 아래 검증 예시와 비교합니다.

## PLC 설정

PLC가 마스터, ESP32가 슬레이브입니다. 38400 bps, 8N1, 국번 7, UART2 TX GPIO14 / RX GPIO15, 방향제어 핀 -1입니다. 같은 RS-485 버스의 모든 장치는 속도와 데이터 형식을 맞추고 슬레이브별로 서로 다른 국번을 사용합니다.

| 홀딩 레지스터 | 통신 오프셋(0부터) | 의미 |
| --- | --- | --- |
| 40009 | 8 | FC06으로 1을 한 번 쓰면 빈 판 학습을 요청. 학습 중 2, 이외 0. 완료는 상태 3으로 확인 |
| 40010~40018 | 9~17 | 1~9번 칸 순서, 각 1워드, 0 없음 / 1 있음 |
| 40019 | 18 | 0 기준 대기, 1 학습 중, 2 초기 판정 중, 3 정상, 4 카메라 오류 |
| 40020 | 19 | 측정 프레임 번호. 65535 다음 0 |

XG5000 예시: FC03, 시작 오프셋 9, 11워드 → 비어 있는 PLC 영역 D100~D110. 그러면 D100~D108이 9칸, D109가 상태, D110이 프레임 번호입니다. 시작 주소를 참조 번호로 받는 화면이라면 40010을 입력합니다. PLC 내부 D주소는 프로젝트에 맞게 선택합니다. 원본의 40001~40008은 이 전용 펌웨어에 할당되어 있지 않습니다.

PLC는 200~500 ms 간격으로 읽고, 읽기가 성공했으며 상태가 3일 때만 칸 값을 사용합니다. 프레임 번호가 여러 폴링 주기 동안 그대로면 측정 갱신 중지로 취급합니다. 통신 단절·초기화·학습 실패를 ‘9칸 전부 비었음’으로 해석하지 않도록 합니다. 40009 외 주소에는 읽기만 사용합니다.

## 판정 방식과 사진 검증

자료에 기재된 블록은 단면 35×35 mm, 길이 35 / 55 / 85 mm입니다. 원본 소형 면적 임계값은 한 물체의 근접 영상용입니다. 새 펌웨어는 실제 지그가 차지하는 화면 크기에 맞게 각 칸 안쪽을 16×16점으로 샘플링합니다. 네 모서리로 원근을 보정하고 칸 너비·높이의 양끝 7%를 제외합니다. 기준 RGB565와 현재 RGB565의 밝기 또는 색 차이가 큰 점을 찾고, 이웃한 2×2 중 3점 이상이 변한 비율을 계산합니다. 블록 크기나 색을 PLC에 분류해 보내지는 않습니다.

기본 진입 기준은 85‰(8.5%), 해제 기준은 55‰(5.5%)이며, 3프레임 연속으로 만족해야 값을 바꿉니다. 웹에서 9개 칸의 변화율을 볼 수 있습니다. src/grid.h의 On, Off는 현장 초기값입니다. 실제 조명에서 빈 칸의 최대 변화율이 해제 기준보다 낮고 35 mm 블록의 최소 변화율이 진입 기준보다 높은지 확인합니다. 두 분포가 겹치면 촬영 각도·반사·조명을 먼저 조정합니다. 손, 집게, 그림자도 화면을 바꾸므로 PLC는 그것들이 물러나고 판정이 안정된 시점에 결과를 사용합니다.

첨부 JPG를 320×240에 맞춰 RGB565로 변환하고 사진마다 네 모서리를 수동 지정한 뒤 동일 C++ 함수를 PC에서 실행했습니다. 아래는 사진 한 프레임의 결과입니다. 시간 필터의 진입·해제 및 좌표 범위는 별도 C++ 시험으로 확인했습니다.

| 시험 | 칸 1~9 변화율(‰) | 진입 기준을 넘은 칸 |
| --- | --- | --- |
| 가로 빈 판(_01)을 동일 이미지와 비교 | 0, 0, 0, 0, 0, 0, 0, 0, 0 | 없음 (기준 자기 비교) |
| 같은 기준으로 블록 배치 사진 검사 | 333, 44, 693, 697, 0, 0, 0, 4, 360 | 1, 3, 4, 9 |
| 같은 기준으로 다른 시점의 세로 빈 판(_02) 검사 | 48, 297, 724, 106, 102, 506, 177, 595, 133 | 2~9번 오검출 |

세로 사진은 촬영 각도와 금속판의 반사가 크게 다릅니다. 카메라를 옮기면 모서리와 배경을 모두 다시 잡고, 조명만 바뀌었으면 빈 판을 다시 학습합니다. 첨부 정지 사진 결과는 실제 ESP32 센서의 반복 정밀도나 PLC 통신 시험을 대신할 수 없습니다.

## 검증 범위

사진 판정 코드와 상태 전환은 PC에서 컴파일·시험했습니다. 전체 PlatformIO 타깃 빌드와 실물 업로드, PLC 응답은 검증 전입니다. 이 ZIP은 소스 프로젝트이며, 업로드할 바이너리는 VS Code에서 이번 소스로 빌드해 생성합니다.

## VS Code 실행 로그
업로드 완료 후 PlatformIO → PROJECT TASKS → esp32cam → Monitor를 엽니다. 모니터를 연 다음 RST를 누르면 부팅부터 볼 수 있습니다. 리셋 뒤에는 빈 판 학습이 필요합니다. USB 모니터는 115200 bps, PLC는 별도 UART의 38400 bps입니다.
모서리 저장, Wi-Fi 연결/IP·끊김, 학습 프레임 수, 상태와 칸 변화가 출력됩니다. 변화가 없어도 5초마다 상태를 출력합니다. cells는 왼쪽부터 1~9번이며 대시 표시는 판정 대기 또는 오류입니다. plc_ok는 이번 부팅 이후 성공한 Modbus 요청 누적 건수입니다.
모니터가 열린 동안 수신한 출력은 PC에도 저장됩니다. 모니터 시작 메시지의 로그 경로를 확인하세요.
